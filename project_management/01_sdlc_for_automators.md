# SDLC for Automators

## Overview
Automation work still needs the same discipline as application development: plan, build, test, review, release, operate, and improve.

## Typical Lifecycle
1. Define the problem and success criteria.
2. Capture the work in a ticket.
3. Design the automation with rollback and observability in mind.
4. Build and test in a safe environment.
5. Review, document, and release.
6. Monitor behavior and feed lessons back into the next iteration.

## Exercises
1. Why does automation need rollback planning?
2. Name two artifacts that should exist before release.
3. Explain why monitoring belongs in the lifecycle.

## Answer Key
1. Automation can change live systems quickly, so rollback reduces blast radius.
2. A reviewed change set and a validation plan are common examples.
3. Monitoring shows whether the automation is helping or harming the environment.
